01 / MOM과 MES를 구분하기

ERP가 무엇을 언제 얼마나 생산할지 결정한다면 MES는 현장 작업이 올바른 자원·공정·조건에서 수행되도록 관리하고 실제 생산 결과를 기록한다. MOM은 제조 운영 전반을 아우르는 범주이며 MES, 품질, 생산 계획·스케줄링, 제조 인텔리전스 등과 연결된다. 아래는 ISA-95의 기능 계층을 쉽게 설명한 개념도다. 시스템의 물리적 배치와 동일하지 않다. [1–3]

Level 4 · ERP수요·계획·재무·구매·출하
Level 3 · MOM/MES작업 배포·실행·품질·이력
Level 2 · SCADA/DCS감시·제어·공정 상태
Level 0–1 · OT물리 공정·센서·액추에이터

PLM ↔ MES

Teamcenter에서 승인된 제품/공정 정의(BOM, BOP, 작업지침 등)를 제조 운영에 활용하고 실제 제조 이력을 연결하는 개념. 어떤 객체와 버전이 자동 연계되는지는 인터페이스와 제품별 검증이 필요하다.

APS ↔ MES ↔ ERP

APS는 제약을 고려해 계획·순서를 수립하고 MES는 실행 현황을 돌려준다. ERP는 재고·원가·오더 관점의 실적을 관리한다. 각 데이터의 소유 시스템을 먼저 정한다.

04 / 데이터 모델과 제조 트랜잭션

아래는 설명용 논리 모델이다. 실제 Opcenter 객체명, 테이블명, 서비스 API가 아니다.

OrderProductionOrder, WorkOrder, PlannedQty, DueDate
ExecutionUnit/LOT, Operation, WorkEvent, Consumption, Inspection
EvidenceGenealogy, Hold, Disposition, Completion, AuditEvent

설계 데이터 vs 실행 데이터

EBOM은 설계 구조, MBOM은 제조 자재 구조, BOP는 제조 작업 절차를 설명한다. 승인 개정, 공장·시점·제품 적용 조건을 합의한 뒤 오더에 연결한다. As-designed / As-planned / As-built의 차이를 증명하는 것이 핵심이다.

실행 상태와 예외

예시: Planned → Released → In progress → Completed. 품질 이상은 Held → 판정 → 재작업 또는 폐기. 상태 전이 권한, 동시성, 취소·보정, 부분 완료, 감사 이력을 명세한다.

추적성

역방향: ECU Serial → PCB LOT → 부품 LOT. 정방향: 문제 LOT → 투입 작업 → 완제품 Serial → 출하 관련 기록. 실제 추적 범위는 수집 입도와 외부 시스템 연계에 의존한다.

검사와 품질 이벤트

검사 항목·단위·상하한·개정·측정값·판정·작업 시점·장비 ID를 연결한다. NG 후 격리·권한자 판정·재검사·불량 원인 분석을 설계한다.

하지 말아야 할 약속

모든 제품에 동일 DB·OS·Kubernetes·API가 있다고 말하지 않는다. 규정 준수 자동 달성, 장애 없는 운영, 지원되지 않는 직접 DB 변경을 약속하지 않는다.

ROI 및 TCO 검토 프레임

연간 편익 = 검증된 폐기·재작업 감소 비용 + 회피 가능한 비용 + 실제 활용 가능한 생산성 개선 가치. 중복 편익 금지. 비용 = 라이선스/구독 + 구축 + 데이터 정제·통합 + 인프라 + 운영·지원 + 교육·검증. ROI = (편익 − 비용) / 비용, 같은 기간으로 비교. 제품 가격·절감률은 견적과 고객 데이터 없이 제시하지 않는다.

11 / 프리세일즈 FAQ · 학습 순서

ERP만으로 충분하지 않나요?

ERP의 생산·재고·회계 기능과 현장 공정 제약, 자재 이력, 작업자 및 설비 이벤트 처리 요구를 비교한다. 중복 구축 여부는 현재 시스템의 실제 기능으로 확인한다.

Teamcenter와 MES가 왜 둘 다 필요한가요?

PLM의 승인된 제품·공정 정의와 MES의 실행·실제 제조 기록은 목적이 다르다. 변경 전파·실적 환류는 통합 범위로 검증한다.

MES가 PLC를 직접 제어하나요?

제어 책임은 일반적으로 OT 시스템에 있다. MES와 설비의 통신 범위는 안전과 제어 아키텍처에 맞춰 정하며, 지원 인터페이스와 장애 시 동작을 검증한다.

규제 준수·전자서명을 보장하나요?

제품 기능과 고객 시스템의 검증·SOP·권한·변경 통제를 구분해야 한다. 특정 규정의 충족 여부는 고객의 품질 및 규제 담당자와 검토한다.

표준 기능인지 커스터마이징인지 어떻게 확인하나요?

대상 버전 매뉴얼과 실제 데모로 요구별 증거를 확보한다. 설정으로 해결할 수 있는지, 확장 또는 별도 개발인지, 업그레이드와 지원에 어떤 영향이 있는지 기록한다.

경쟁 MES 대비 장점은?

같은 고객 요구·제품 버전·범위·성능 조건에서 비교한다. PLM–MES 연결, 산업별 기능, 통합과 운영 비용은 평가 축이지 검증되지 않은 우위의 근거가 아니다.
